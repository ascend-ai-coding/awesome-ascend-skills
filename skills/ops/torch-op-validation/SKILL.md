# PyTorch 算子验收

适用于迁移回归、算子发布和问题定位。单纯测单算子延迟时使用 `npu-op-benchmark`；开发 AscendC 内核时使用 `ascendc`。本技能不安装或更换设备驱动、CANN 或框架。

## 快速开始

1. 填写 [任务示例](assets/task-example.json) 中的算子、环境和验收依据。单个 API 可以只给调用形参；批量任务从已有清单展开。
2. 如要求按《昇腾算子精度标准 2.1》验收，先按 [精度与用例](references/precision.md) 核对标准修订版、级别、算子类别和执行要求。小样、诊断和正式验收必须分开。
3. 按 [ATK 执行与复现](references/atk.md) 验证安装、节点、输入和报告链路，然后执行用例。ATK 配置和插件取自所用版本的示例或经过实测的实现。
4. 按 [报告格式](references/report.md) 将真实结果整理成 JSON，生成可离线查看的 HTML 和 CSV。可先用合成示例检查输出：

   ```bash
   python3 scripts/render_report.py assets/report-example.json --out ./example-report
   ```

## 执行要点

- 同一用例的各执行端共用冻结输入、参数和上游梯度；记录输入来源和哈希。对原位、多输出、视图、异步或分布式 API，还需保留别名、状态、顺序和完成边界。
- 泛化、模型形状、模型真实输入和特殊用例分别统计。由 profile 取得形状后构造的数据不是实际模型输入。
- 2.1 浮点双标杆使用同一个高精度 Golden 计算候选和对照的误差，再比较误差比。项目另有逐位或绝对误差要求时另列，不替代 2.1 判定。ATK 报告通过也不等于用例规模和设备覆盖达标。
- 保留计划与实际的用例 ID、各阶段和各设备的完成情况。执行错误、无标杆、未运行和不支持不得计为通过。
- 仅在获准且空闲的设备上测量。功能与精度结果可以复用同一次执行取得的证据；内存、计时和确定性分别采集，见 [专项测量](references/specialized-tests.md)。
- 对能够由 ATK 执行的失败优先交付单用例复现包，真正重新调用算子并核对原失败签名。用已保存输出验证比较器是另一种检查。涉及私有数据时仅交付获准使用的输入或公开替代示例。
