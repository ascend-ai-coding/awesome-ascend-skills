# 精度依据与用例设计

## 选定验收依据

本 Skill 以《昇腾算子精度标准 2.1》作为精度验收主标准。原标准面向 Kernel 及包含一个或多个 Kernel 的 ACLNN API；本 Skill 将适用要求落实到 PyTorch/TorchNPU API，记录公开调用、重载与底层算子的语义对应。记录采用的修订版、来源标识和摘要哈希、算子类别、L0/L1/L2 等级及分级依据。L0 为常规算子，L1 为重要算子，L2 为关键算子。

报告区分冒烟测试、问题定位、项目回归和正式验收。ATK case JSON 的 `version: v2.1` 是配置格式标识，ATK 默认精度结果是工具结果，均不能单独证明符合本标准。正式通过须同时核对适用判据、用例和样本覆盖、执行策略、设备平台及复检证据。公开商用精度文档可辅助查阅，但未标明 2.1 修订号，不能替代本轮采用的标准版本。[公开参考](https://github.com/ascend-ai-coding/awesome-ascend-skills/blob/75ec89ce9d401be8ac95980e1c3f42f8d4315057/external/cannbot/ops/ops-precision-standard/reference/golden/COMMERCIAL_OPS_PRECISION_DOCS.md)

项目逐位一致或绝对误差要求属于可选附加检查，使用独立的 `project-regression` 规则和结果。项目 P0/P1 等优先级不能映射为精度 L0/L1，也不能替代 2.1 判定。

## 标杆和算子分类

单标杆是候选与一个参考实现直接比较；计算类的单标杆须为更高精度实现。双标杆使用同一份高精度 Golden，分别计算 NPU 候选和同精度对照相对 Golden 的误差，再比较两端误差。通常以高精度 CPU 为 Golden、GPU 为对照；标准允许同精度 CPU 或昇腾小算子拼接实现承担对照角色，必须记录适用条件和实现。

标杆遵循竞品对标优先、逐级选择备选的原则：对应框架已有的业界 CPU 或第三方芯片实现；无对应竞品的融合算子、特殊融合结构或明确特殊需求采用等效小算子组合；非标准数据类型采用自行构造的 CPU 实现。涉及串联量化/反量化的量化算子也可采用组合实现。保留源码、版本和等效性依据。

各端使用冻结的相同输入、属性和上游梯度，记录输入哈希、权重、累加精度、输出 dtype 和计算模式。Golden 的计算精度应高于被评估实现；FP16/BF16 输入通常用 FP32 计算，但不得仅凭输出 dtype 声称实现具有更高计算精度。

| 类别 | 范围 | 比对与通过条件 |
| --- | --- | --- |
| 非计算类 | 搬移、复制、转换，如 transpose、gather、scatter、copy、cast | 单标杆，输出二进制一致 |
| 整数计算类 | 输入与输出均为整型的计算 | 单标杆，二进制一致；二进制不一致但逐点绝对误差为 0 也通过 |
| 量化计算类 | 模型量化过程中的低/高精度转换和计算 | 按下表选择整型输出或浮点输出规则 |
| 浮点计算类 | 使用浮点表示进行数值计算 | 双标杆，同时检查正常值域、小值域及适用的非有限值规则 |
| 随机数生成类 | 按指定分布产生随机数，如 rand | 独立于上述四类，使用分布检验规则 |

类别由算子语义与计算过程确定，不能只按输入 dtype 判断。所有类别都需检查返回结构、shape 和 dtype；位比较使用原 dtype，保留符号零及特殊值位模式。

| 量化输入类型 | 整型输出（INT4/INT8/INT16 等） | 浮点输出（FLOAT4/FLOAT8/FLOAT16 等） |
| --- | --- | --- |
| 整型输入（INT4/INT8 等） | 标准表为 N/A，记录适用性说明，不据此宣称通过 | 按浮点双标杆标准 |
| 浮点输入（FLOAT4/FLOAT8/FLOAT16 等） | 单标杆，逐点绝对误差 `AE <= 1` | 按浮点双标杆标准 |

## 浮点误差和通过阈值

前向对各返回叶子分别评价；反向对 input、weight 等所需梯度分别评价。两阶段各自记录类别、等级、三方结果、初判和适用的复检，检查返回结构及 None 梯度的预期行为。训练反向还需遵守下文正反向级联要求。

对可作数值比较的输出元素，令 `AE = abs(actual - golden)`、`RE = AE / (abs(golden) + 1e-7)`，则 `MARE = max(RE)`、`MERE = mean(RE)`、`RMSE = sqrt(mean((actual - golden)^2))`。三项分别在候选和对照相对同一 Golden 的结果上计算；多输出和反向梯度保留各叶子的指标及适用范围。记录统计元素的掩码、数量及值域拆分依据，不能静默丢弃未满足要求的输出。

### 正常值域

每项误差指标都使用 `Ratio = metric_npu / max(metric_peer, err)`，三项比值均须满足对应等级上限。`err` 是普通误差比分母的独立下限，不能省略，也不是逐点 RE 分母中的 `1e-7`。

按 2.1 第 4.5.1 节，正常误差比的 `err` 取相应 dtype 的 Small Value Threshold（下表 `threshold`），不是第 4.5.3 节用于计错的 `error`。例如 BF16 的正常比值分母下限为 `2^-8`，小值域绝对误差界为 `2^-16`；逐点 RE 的稳定项仍为 `1e-7`。报告分别记录 `ratio_denominator_err`、`ratio_err_source`、`ratio_err_interpretation`，保留三者的用途。采用原文的表项或框架 dtype 映射无法确定时，才将受影响的条目标为待核对。

| 等级 | 独立普通用例/算子 | 每种支持 dtype 的普通用例 | 每例精度执行次数 | MARE / MERE / RMSE 比值上限 |
| --- | ---: | --- | ---: | --- |
| L0 | >= 5,000 | >= 200 | 50 | 10 / 2 / 2 |
| L1 | >= 10,000 | >= 700 | 50 | 5 / 1.5 / 1.5 |
| L2 | >= 30,000 | 按所用原表的合并/继承项核对并记录 | 1,000 | 2 / 1.2 / 1.2 |

L2 要求在泛化用例基础上增加真实业务模型训练和推理输入。若文本转录未保留 dtype 等单元格的合并关系，应核对相应表项，不能把未显示的继承值写成原文独立条款。

保存两端相对 Golden 的原始 MARE/MERE/RMSE、实际分母和比值。ATK 的 `cv_fused_double_benchmark` 常见对应参数为 `max_re_ratio`、`avg_re_ratio` 和 `root_mean_squared_ratio`；用已知结果的小样核对本版节点角色、分母下限、参数含义、输出字段和 `<=` 边界。工具与标准存在未解释差异时，仅报告工具或诊断结果。误差均衡指标可用于排查，不替代通过条件。

### 小值域

在 `abs(golden) < threshold` 的元素中，统计 `abs(actual - golden) > error` 的个数，得到各端 `ErrorCount`。通过条件为 `ErrorCount_npu / max(ErrorCount_peer, 1) <= 2`，适用于所有数据类型；严格保留筛选中的 `<`、计错中的 `>` 和比值中的 `<=`。

| 标准中的 dtype 名称 | threshold（Small Value Threshold） | error |
| --- | --- | --- |
| FLOAT16 | `2^-11` | `2^-16` |
| BFLOAT16 | `2^-8` | `2^-16` |
| FLOAT32 | `2^-14` | `2^-30` |
| HiFLOAT32 | `2^-12` | `2^-28` |
| FLOAT8 E4M3 | `2^-4` | `2^-6` |
| FLOAT8 E5M2 | `2^-3` | `2^-5` |
| FLOAT4 E1M2 | `2^-2` | `2^-4` |
| FLOAT4 E3M0 | `2^0` | `2^-2` |

表中保留标准名称，包括 `HiFLOAT32` 和 `FLOAT4 E1M2`。实际框架类型与这些名称的映射需确认，不能自动改成其他格式。分别记录 `small_value_threshold`、`small_value_error`、小值元素数、两端错误数和计数比；该表的 error 不自动决定正常值域的分母下限。

### Inf、-Inf 和 NaN

非有限输出不能直接计算相对或绝对误差；按位置比对 Golden、NPU 和对照，并结合算子公式判断。记录种类、符号、位置、芯片型号与 `INF_NAN_MODE_ENABLE` 的实际值，不能过滤后以有限值比较结果代替此检查。

Ascend910A 及之前平台，或 Ascend910B 及之后平台且 `INF_NAN_MODE_ENABLE=0` 时，标准规定 inf 计算值不参与精度比较，需单列排除数量及依据。该条款不能扩大为所有 NaN 或所有异常输出都豁免。Ascend910B 及之后且 `INF_NAN_MODE_ENABLE=1` 时，要求 inf 输出一致，或 NPU 相对高精度 Golden 更接近正确值。

- NPU 与对照的非有限输出一致时，可按标准正确条件通过该位置，与 Golden 的值无关。
- Golden 为 inf/-inf/nan，且 NPU 与 Golden 完全一致时，该位置正确，即使对照与 Golden 不同。
- Golden 为 inf/-inf/nan，对照与 Golden 一致而 NPU 不一致时，判为计算错误。
- Golden、NPU、对照三者都不一致时，进一步核查 Golden 与对照的有效性，记录待查状态。未被明确规则覆盖的组合结合公式核实，不能默认通过。

## 失败后的复现与复检

单个浮点用例初判不满足通过标准时启动复检。保留初判、用原输入复现，再以相同用例定义更换随机种子生成输入，得到 `N` 个误差比样本，推荐 `N=1000`。新种子不增加独立用例规模，同一输入的压测和确定性重复也不代替复检采样。

按 2.1 附录 5.3.4，对 `N` 个样本进行 **2000 次**有放回重采样，每次抽取 `N` 个样本并计算中位数，用这些中位数的 2.5% 和 97.5% 分位数构成 95% 置信区间。推荐的 1000 是换种子样本数；正文关于 1000 次重采样及第 25/976 个中位数的举例不能替代附录明确的 2000 次方案。

`N < 200` 时直接判复检不通过，不做小样本统计推断；`N >= 200` 且 `CI_lower > 1.0` 时复检不通过，其余情况按该复检规则通过。阈值是 `1.0`，不替换为 L0/L1/L2 的初判上限。按各受检指标分别保留误差比样本、采样种子、Bootstrap 种子、重采样次数、分位数实现/插值方法、区间和结论。复检通过不免除其他指标、覆盖、执行次数或设备要求。

## 随机数生成类

对整张量使用 KS 检验比较生成分布与标杆，显著性水平 `alpha=0.01`，单次要求 `p > alpha`，等于阈值不通过。跨不同 shape 重复 `N` 次，标准给出 `N=100` 的可选规模，固定常数 `z=-3.0902`。记录检验实现、标杆分布、shape、样本数、种子、每次 p 值、通过个数及总比例。

总通过比例公式涉及 `alpha`、`z`、`N`；若取得的文本丢失根号、分式等结构，不能直接执行残缺表达式或自行补公式。仅将受影响的随机数生成类总体验收条目标为待确认，获取完整公式后记录版本和实际阈值；其余类别仍按各自明确条款验收。随机 API 的分布通过也不代替功能或适用的 RNG 确定性检查。

## 生成与核验用例

单个用例由明确的输入 Tensor 与 Attr 定义；不同种子、重试和重复执行均记在原用例下。普通用例覆盖所有支持 dtype、格式（如 ND/NCHW/FRACTAL_NZ）、维度和属性，dtype、格式、维度与参数类型相互正交。维度数 1–8，维度值范围 `1–2^31`，总元素数 `<= 2^34`，均需服从算子实际支持范围。标量属性覆盖等价类，布尔覆盖 True/False，枚举覆盖所有支持值，并组合遍历参数类型。若转录丢失指数格式，应核对原表，不能把 `2^31`、`2^34` 误读为整数 231、234。

| 等级 | 形状生成 | 数据分布 |
| --- | --- | --- |
| L0 | 覆盖所有支持维度数，维度值按步长 15、16 泛化 | 均匀 `[-5,5]` 占 50%；正态占 50% |
| L1 | 覆盖所有支持维度数，维度值随机 | 均匀 `[-0.001,0.001]` 占 10%；均匀 `[-5,5]` 占 30%；正态占 40%；离群点分布占 20% |
| L2 | 在泛化用例基础上加入实际业务模型训练和推理输入 | 泛化用例 : 模型用例 = 2:1；记录泛化分布的继承依据及实际覆盖 |

正态分布的 `mu` 在 `[-100,100]`、`sigma` 在 `[1,25]` 内随机选取；合法输入域不允许这些取值时，记录约束、适配方法及无法覆盖项，不静默计为覆盖。

离群点分布先生成均匀或正态基础张量。对总元素数为 `n > 0` 的每个参与数值计算的输入，独立随机、无放回选择 `k=max(1,floor(n/1000))` 个位置，将其值乘以 1000，其余保持不变。校验所有值仍满足算子有效输入域，越界时重新生成基础数据或调整倍率并记录。多输入的离群位置独立采样；索引、形状等不参与数值计算的输入保持原值。空张量按特殊场景处理。

| 来源 | 设计方法 | 证据 |
| --- | --- | --- |
| `generic` | 按等级和语义约束生成普通用例，完成上述正交与分布覆盖 | 生成器修订版、配置、种子、分布和覆盖统计 |
| `model_shape` | 从实际模型调用读取形状及属性，以构造数据生成输入 | 模型或模块、阶段、调用来源、构造记录 |
| `model_dump` | 使用实际业务调用输入，冻结张量、属性、梯度和存储关系 | 数据来源、输入哈希与实际覆盖范围 |
| `boundary` | 按下表生成特殊值、边界和异常用例 | 预期行为、资料说明、拦截代码和实测结果 |

L2 模型份额要求实际业务模型训练和推理输入。`model_shape` 仅证明调用形状来源，不能仅凭该标签计入真实模型输入份额；需要相应证据与条款依据。所有测试用例输出样本点的总元素数不得低于 1,000,000。报告同时保留去重用例的输出元素数和含重复采样的输出样本数，注明所用条款的统计范围；种子与执行次数不能充抵独立用例规模。

### 特殊场景覆盖

特殊场景不计入普通用例规模，按每种支持 dtype 和维度分别核对。

| 场景 | 要求 |
| --- | --- |
| 空 Tensor | 对 `d` 维 Tensor 逐个将某一维设为 0，其余为非负整数，每 dtype、每维度数生成 `d` 个 |
| 下边界 | shape 所有维度均为 1，每 dtype、每维度数一个 |
| 上边界 | 逐个将某一维设为 `2^31+1`、其余维为 1，每 dtype、每维度数生成 `d` 个；记录支持或拦截行为 |
| 标量 Tensor | shape 为 `[1]`，每 dtype 一个 |
| 非有限输入 | 遍历全 nan、全 inf、全 -inf、包含 -inf 与 inf 四种模式；每 dtype、每模式 4 个不同 shape，用于所有输入 Tensor |
| Tensor/Attr 异常 | 覆盖值域边界外、算子约束外和不支持场景，核对资料说明及明确的代码防护或拦截 |

### 训练与推理输入

训练反向算子精度评估须采用正反向级联，在候选、对照和 Golden 各自执行前向后再执行反向，保留上游梯度和各端缓存的对应关系。FlashAttentionScoredGrad、Norm 等依赖前向中间量的反向尤其需要检查累计误差，不能给各端混用另一端的缓存。记录前向、反向、优化器阶段及分布式信息。

推理区分 prefill 和 decode，记录上下文长度、批大小、动态形状及执行模式。输入清单保留 dtype、shape、stride、布局、offset、别名、标量参数和可微性。原位、有状态用例每轮恢复初始状态；视图保留存储关系，异步和分布式操作等待完成后采集。

训练 RMSNorm 可采集 packing 的不同 token 数，保存输入、权重、末维和 eps；推理注意力分别记录 prefill/decode 的 Q/K/V 头数、长度、布局和掩码。批量采集按重载和阶段记录模型版本、模块、采样区间及采集方式。[任务示例](../assets/task-example.json)
