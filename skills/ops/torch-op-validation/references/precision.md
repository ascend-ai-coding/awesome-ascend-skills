# 精度依据与用例设计

## 选定验收依据

如果任务指定《昇腾算子精度标准 2.1》，将该版本作为精度验收依据。记录标准来源、修订号、文件哈希、算子类别和等级；取得获准使用的对应修订版后再做正式判定。仓库中同步的 [CANN 商用算子精度文档](https://github.com/ascend-ai-coding/awesome-ascend-skills/blob/75ec89ce9d401be8ac95980e1c3f42f8d4315057/external/cannbot/ops/ops-precision-standard/reference/golden/COMMERCIAL_OPS_PRECISION_DOCS.md) 提供可公开查阅的规则。同步文档未明确标注 2.1 修订号，不能据此替代项目指定版本。ATK wheel 版本、配置 JSON 的 `version` 和精度标准修订号是不同的信息。

预先说明用例是用于冒烟、定位问题、项目回归还是正式验收。缺标准原文、等级、平台覆盖、实测结果或复检证据时，保留已有结果并明确哪些要求未验证。不能由用户指定的几组形状推断已达到 L1 或 L2。

## 双标杆与算子分类

- 对适用的浮点计算，将候选端和同精度对照端分别与同一个高精度 Golden 比较。CPU 可承担 Golden，第三方设备可承担对照；通过条件使用候选误差除以对照误差。优先用同语义的成熟实现；只有标准允许时才用等价组合实现，记录条件和实现源码。两端不能共用低精度输出充当 Golden。
- 从冻结的实际输入精度提升 Golden 计算精度。FP16/BF16 至 FP32 是常见选择，而 FP32、复数、量化及特殊 dtype 应按批准标准和算子语义明确选择。记录权重、上游梯度、累加精度、输出 dtype 和设备执行模式。
- 正常值域的相对误差按官方定义使用 `abs(golden) + 1e-7`，分别计算最大相对误差（MARE）、平均相对误差（MERE）和均方根误差（RMSE）。运行前验证所使用的比较器如何处理零或极小对照误差；不得悄悄加入分母下限。差异无法说明则仅作为诊断结果。
- 非计算、整数、量化、随机数按原文对应类别单独判定。例如非计算类检查与单标杆的位一致，整数还要满足返回结构和 dtype；浮点转量化整数、随机数生成和浮点计算不是同一类。
- 小值域按对应 dtype 的界限统计两端超差元素，不用普通相对误差替代。Inf/-Inf/NaN 按原文三方判定和设备模式检查并保留数量、符号、位置与待排查项；不能通过掩码把差异删掉。记录无有效元素、特殊规则不适用等情况。
- 初判失败时保留原用例，再按标准以新种子完成复检；不要用重跑一次通过替代复检。公开参考要求至少 200 个新种子样本、推荐 1000 个，以 2000 次有放回重采样估计中位数的 95% 置信区间；下界大于 1 判不通过。报告被复检指标、样本量、分位数方法、区间和结论。

公开参考的正常值域阈值和规模如下。运用于正式项目时须与该项目已批准修订版核对；不能只核对这一张表。

| 等级 | 独立普通用例/算子 | 每种支持 dtype | 每例精度执行次数 | MARE / MERE / RMSE 比值上限 |
| --- | ---: | ---: | ---: | --- |
| L0 | 5,000 | 200 | 50 | 10 / 2 / 2 |
| L1 | 10,000 | 700 | 50 | 5 / 1.5 / 1.5 |
| L2 | 30,000 | 700 | 1,000 | 2 / 1.2 / 1.2 |

三项比值均须满足各自上限；保留原始误差及比值。ATK 若支持 `cv_fused_double_benchmark`，核对三个参数与准则的映射；先用已知数值检验比较结果。工具还须证明实际用了正确的 Golden 和对照，不能仅凭配置名确认标准合规。

例如项目额外要求前向逐位一致或所有元素绝对误差严格小于 `1e-4`，另报 `project-regression` 结果。绝对误差等于 `1e-4` 不通过且不加相对容差。按位比较保留原 dtype，检查符号零、特殊值位模式及输出结构。有些项目把外部 GPU 作为直接回归标杆，此角色与 2.1 的同精度对照不同，两项结论互不覆盖。

## 生成与核验用例

| 来源 | 设计方法 | 证据 |
| --- | --- | --- |
| `generic` | 在合法范围对 dtype、格式、维度、标量和属性安排正交覆盖。按标准区分近零、一般均匀、正态及离群值，处理索引、缩放和通信等约束。 | 生成器修订版、配置、种子、分布和覆盖统计 |
| `model_shape` | 从训练或推理调用读取真实形状及可见属性，用公开或获准的构造数据生成用例。 | 模型或模块、阶段、调用来源、构造记录 |
| `model_dump` | 使用获准的实际调用输入，冻结张量、属性、梯度和存储关系。 | 数据来源、哈希、权限与实际覆盖范围 |
| `boundary` | 空张量、标量、上下界、非有限值、非法参数等；与普通用例分报。 | 预期行为及实际结果 |

训练记录前向、反向、优化器阶段和分布式信息；需要缓存的反向由本端前向产生中间值，完成正反向级联，不将另一端的中间值替换进来。推理区分 prefill/decode、上下文长度、批大小和动态形状。保存各输入的 dtype、shape、stride、布局、offset、别名、标量参数、可微性；缺信息就标明，不推测为真实输入。

按标准统计独立普通用例；换种子、重试、重复执行或派生特殊用例不增加独立普通用例数。核查每种支持 dtype 和格式、适用设备平台以及至少一百万输出元素。L2 核查泛化与合格模型用例的 2:1 分配；仅有模型形状和构造值时，除非批准的标准明确允许，否则不计入真实模型份额。记录每级计划/实测、来源分布、排除原因、输出元素和每案执行次数。精度执行压力测试与额外确定性验证分开记录。

### 训练与推理样本的记录

对单算子先从 [任务示例](../assets/task-example.json) 确认输入列表和梯度；批量场景按算子重载及调用阶段拆分。为来源相同的训练/推理样本保留模型版本、模块、阶段、采样时间窗口、参数定义和采集方式。同一 API 的训练反向和推理调用可共享名称，但不能共享不相容的形状或假定参数默认值。示例中的解码形状是构造示范，不代表任何模型实际观测。

例如训练 RMSNorm 可采集 token 数随 packing 变化的输入及权重，保存归一化末维和 eps；推理注意力应分别采集 prefill 和 decode，保存 Q/K/V 的头数、长度、布局、掩码和属性。泛化档补齐非整齐维度、不同布局、等价参数类别和支持 dtype；实际模型档保留发生过的调用，不将无业务来源的扩展形状计入该档。
