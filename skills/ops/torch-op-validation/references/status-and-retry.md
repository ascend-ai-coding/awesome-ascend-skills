# 状态处理与有限重测

HTML 概览按四类显示；CSV、明细和平台附件保留原始状态，区分数值失败、执行异常、缺资料和仅有测量。

| 概览 | 原始状态 | 处理 |
| --- | --- | --- |
| 通过 | PASS | 已满足该条专项判据；还需另外核对算子正式验收范围 |
| 不通过 | FAIL | 保留初判和输入，精度失败按 2.1 复现、复检 |
| 待处理 | ERROR / TIMEOUT | 先查报错或超时原因，确认原任务已退出后再有限重跑 |
| 待处理 | BLOCKED / NOT_RUN | 补齐参数、标杆、证据或资源；条件恢复后执行缺项 |
| 待处理 | MEASURED | 已取得测量。能按既定判据评定时补判；未设门槛的诊断或性能测量可保留，不必重跑 |
| 待处理 | UNSUPPORTED | 核对实际版本和支持范围；必测项不能自动排除，也不能反复重跑解决 |
| 不适用 | NOT_APPLICABLE | 保存不适用依据；它不是通过，也不能用于豁免必测项 |

合成示例在 Allure 中统一显示 skipped；实际执行结果按原始记录映射。

## 批量前先排除可避免的问题

先核对 API 重载、输入及属性、dtype / shape / layout、前后向和上游梯度；缺少参数时结合调用代码补齐并记录来源，保留指定形状。分组检查设备、ATK 版本、插件导入、输入路径、三方角色与 Golden dtype；每种适配器或特殊模式先运行一个最小用例，成功后再扩展该组。

冻结计划后再计完成数。资源、认证或兼容性问题影响整组时，记录原因并等待或暂停该组；恢复后从缺项继续。复用记录注明原执行时间和来源，未运行项保留 NOT_RUN。

## 修复后只重跑受影响项

以下供 Agent 执行。临时环境故障修复后最多补跑两次；用户规定更少时遵从用户要求。同一原因修复后再次出现即停止该项。

1. 保存原日志、退出码和失败签名，区分环境错误与数值失败。SSH 断线、超时或回执不明时，先核查原进程和作业状态，再决定是否重提。
2. 确认原因并在已有授权内修复，例如修正插件路径、补齐文件或调用参数、等待空闲资源。修复时保持既定 Torch / CANN 版本、dtype / shape、覆盖和阈值；内存不足先检查残留和并发。环境或用例变更另行记录和评估。
3. 每次使用新的 attempt 目录；同一用例重测保留原 case_id、输入与梯度哈希、角色、标准、测量范围，重跑前恢复状态。若修正参数改变了用例定义，另建关联用例并保留差异，不称为原输入复现。只重跑受影响的用例、阶段和后端；前后向有缓存依赖时重做该端前向。标杆方案改动后按依赖重算参考结果和比较。
4. 已有完整输出时，优先补解析、索引或判定，减少重复调用；无法从原记录确认的数据保留缺失状态。
5. 每个行键保留一条当前结果，在 metadata.attempts 中引用各次目录、状态、原因和输入身份，保留首错、失败尝试及恢复经过。重试仍计入原用例。

精度 FAIL、确定性差异和内存超限按对应标准复现、分析和复检，不以某次偶然通过覆盖原失败。更换种子的统计复检按[2.1 复检要求](precision.md#失败后的复现与复检)执行，与环境故障补跑分别计数。

## 收尾检查

交付前逐项处理缺参、缺判定和可恢复故障；无门槛的测量保留 MEASURED，无法恢复项写明下一步。2.1 判据、Allure 映射和 Grafana 原始指标保持不变。
