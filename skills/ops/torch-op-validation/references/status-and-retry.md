# 状态处理与有限重测

状态较多，是因为数值不通过、程序没跑完、缺资料和仅有测量不能用同一种结果表示。HTML 概览只显示四类，CSV、逐条明细及平台附件保留原状态，便于查原因。

| 概览 | 原始状态 | 处理 |
| --- | --- | --- |
| 通过 | PASS | 已满足该条专项判据；还需另外核对算子正式验收范围 |
| 不通过 | FAIL | 保留初判和输入，精度失败按 2.1 复现、复检 |
| 待处理 | ERROR / TIMEOUT | 先查报错或超时原因，确认原任务已退出后再有限重跑 |
| 待处理 | BLOCKED / NOT_RUN | 补齐参数、标杆、证据或资源；条件恢复后执行缺项 |
| 待处理 | MEASURED | 已取得测量。能按既定判据评定时补判；未设门槛的诊断或性能测量可保留，不必重跑 |
| 待处理 | UNSUPPORTED | 核对实际版本和支持范围；必测项不能自动排除，也不能反复重跑解决 |
| 不适用 | NOT_APPLICABLE | 保存不适用依据；它不是通过，也不能用于豁免必测项 |

示例中的 synthetic、NOT_RUN 或 Allure skipped 往往是为了演示结构，不表示真实设备连续测试失败。平台状态只是映射，不能为减少 skipped / broken 而修改原始结论。

## 批量前先排除可避免的问题

先核对 API 重载、输入及属性、dtype / shape / layout、前后向和上游梯度；缺少参数时结合调用代码补齐并记录来源，不能为跑通而猜参数或改变指定形状。分组检查设备、ATK 版本、插件导入、输入路径、三方角色与 Golden dtype；每种适配器或特殊模式先运行一个最小用例，成功后再扩展该组。

把计划冻结后再计完成数。无资源、认证缺失或环境不兼容时记录原因，按授权等待或暂停该组。不要把剩余同类用例逐个启动再报相同错误，也不要把未运行批量改为通过。已确认的证据可复用，但不能用历史输出伪装新设备执行。

## 修复后只重跑受影响项

这是 Agent 执行指令，不是自动重试服务或调度器。默认首次执行后，因临时环境故障最多补跑两次；用户规定更少时遵从用户要求。同一原因修复后再次出现即停止该项，不把重试预算当作必须用完。

1. 保存原日志、退出码和失败签名，区分插件/路径错误、资源问题与算子数值失败。SSH 断线、超时或回执不明时，先检查原进程和作业，不能直接提交重复任务。
2. 只有确认原因且能在已有授权内修复时才补跑。例如修正插件导入路径、补齐缺文件或真实调用参数、等待获准空闲资源。不得自动升级 Torch / CANN、替换规定 dtype / shape、降低覆盖或放宽阈值。内存不足先检查残留和并发，不缩小用例冒充原结果。
3. 每次使用新的 attempt 目录；同一用例重测保留原 case_id、输入与梯度哈希、角色、标准、测量范围，重跑前恢复状态。若修正参数改变了用例定义，另建关联用例并保留差异，不称为原输入复现。只重跑受影响的用例、阶段和后端；前后向有缓存依赖时重做该端前向。标杆方案改动后按依赖重算参考结果和比较。
4. 已有完整输出而只缺报告解析、文件索引或判定记录时，先补处理，不重新调用算子。无法从原记录确认的数据继续标缺失；不能补写未经实际检查的通过声明。
5. 最终结果按原行键只保留一条当前记录，在 metadata.attempts 中引用每次目录、状态、原因及是否同一输入，附原始证据。首错与失败重试不可删除；修复后通过也要保留恢复经过。汇总时重试不增算独立用例。

真实精度 FAIL、确定性差异和内存超限不能靠重跑挑一次通过。按相应标准复现、分析和复检；更换种子的统计复检按[2.1 复检要求](precision.md#失败后的复现与复检)执行，不受上述“临时环境故障补跑两次”替代。未达到要求时如实保留未完成或失败结论。

## 收尾检查

交付前逐项检查待处理原因：能补参数的补参数，能从原输出补判的补判，能在授权内修复的有限重跑。保留确实没有门槛的测量和无法恢复项，并写明下一步。报告归类只降低阅读负担，不改变 2.1、Allure 原状态映射或 Grafana 原始指标。
