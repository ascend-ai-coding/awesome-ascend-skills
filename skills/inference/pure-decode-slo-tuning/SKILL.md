# 纯 Decode SLO 寻优

目标是在**指定工作负载与 SLO 下找到最高合规 QPS**。保留原始启动脚本和每轮证据；将单轮筛选、最终全量确认、后续追加配置验证分开表述。用户指定的 SLO、数据顺序、benchmark 参数、请求数与收尾状态优先；不要把本次 A5 的数值当成下次默认值。

## 开始前

先读 [完整执行流程](references/workflow.md)。需要撰写或审查最终交付时再读 [报告结构与验收](references/report.md)。`scripts/derive_pured_tpot.py` 可从真实接受率 JSON 和假 KV benchmark JSON 计算折算 TPOT；运行前核对输入字段与当前镜像版本。

**用户必须指定数据集、模型及权重**：至少给出数据集名称或文件位置、模型名称和权重位置；不能因机器上已有文件或旧报告使用过它们就自行选定。若这些输入缺失，先询问用户，同时可做不依赖它们的环境检查。用户指定后再锁定实验契约：镜像及版本、卡数及合法 DP×TP、原始脚本、数据集 SHA256/行数/长度分布、输出政策、benchmark 完整命令、SLO 公式/分位数/阈值/成功率、超时、资源上限、最终容器状态。数据集身份、模型配置和权重完整性由执行者核验，不要求用户提供哈希。区分 `--gpu-memory-utilization` 显存分配比例与 NPU 算力利用率。确认容器归属和已有占卡进程；只停止本任务容器或用户明确授权的容器，不删除他人的容器或镜像。

## 不可跳过的次序

1. **原始脚本基线与切分。** 不继承上一轮报告的参数。固定原始脚本的非切分配置，逐一验证合法 DP×TP；健康检查所有 rank、代理和模型，再做 canary。启动失败保留日志，不能记作 0 QPS。
2. **MNS/MBT 组合与并发爬坡。** 在可运行切分下列出实际待测组合，逐组从低并发粗爬坡、在 SLO 附近细化，记录最高合规 QPS 和相邻边界。每个组合独立爬坡，不能只在一个固定 cc 横向比较。此阶段主要改 MNS/MBT；若某组合因明确的通信缓冲错误无法启动，可按证据最小幅度调整 HCCL 后重新测，并将该兼容性例外单独标注。常规 HCCL 寻优留到参数验证阶段。
3. **参数验证。** 选 MNS/MBT 阶段最高合规 QPS 的组合为基线，逐个参数族验证显存比例、调度/图模式、HCCL/通信、block size、prefix cache、SWA bounded replay、权重/KV 布局等当前镜像实际支持的项。只改单参数族；对可能改变容量的候选重新找合规 cc。没有爬坡的固定 cc A/B 只能称对照，不能用于最高容量排名。
4. **投机配置。** 每个候选 K 和 draft sampling 先在真实 Prefill+Decode 路径测逐位置接受率与 `AL_K`，再把对应 rates 注入 `DecodeBenchConnector` 的 synthetic rejection；独立爬坡。没有真实接受率的候选不得沿用别的 K/采样模式的 AL。无投机可作为对照。
5. **最终确认。** 快速筛选点的请求数可按用户约定取实际并发的约 3–4 倍，保持同一数据顺序；只有选出最终并行配置、参数和 cc 后才跑一次指定全量，并核验全部完成、输出长度、SLO、Running/Waiting。另列无约束吞吐峰值，不能混作合规容量。若最终脚本再增加开关，重新测该组合；旧脚本的边界结论不可直接继承。
6. **交付和收尾。** 生成可在另一台机器复现的报告与完整脚本，验证路径、代码块、结果与指标一致。按用户要求恢复、保留或停止本任务容器，核查所有 rank 或 NPU 占用，准确记录最终状态。

## 判定口径

当用户指定 `TPOT P50 = ITL P50 / AL_K`，所有假 KV TPOT 分位数均用**固定的真实请求 AL** 折算；假 KV 随机实现 AL 只用于核验注入效果，benchmark 原生 TPOT 不能替代此公式。`AL_K = 1 + sum(前 K 个逐位置接受率)`。真实接受率若只测样本，必须写明样本量与选择方式，不能称全量 AL。

每个有效点保存请求成功/失败、输入/输出 token、QPS、输出 token/s、TTFT、ITL、折算 TPOT、实际 Running/Waiting、启动与 benchmark 日志。确认请求输出政策确实生效；`--custom-output-len` 的具体语义以当前 `vllm bench serve` 实现和生成 token 数核验。比较不同轮次时必须标明短样本或全量、是否忽略 EOS、温度和数据顺序。高并发出现排队、OOM 或代理限流时查实际指标，不把 offered cc 当作 NPU 运行并发。

完整流程以 [执行流程](references/workflow.md) 和 [报告验收](references/report.md) 为准；阶段结果不足时保留明确的“未测/失败/仅筛选”状态，不补造最优结论。
